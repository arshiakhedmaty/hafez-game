# HAFEZ GAME — Arshia & Rojina

یک بازی **دو نفره‌ی همکاری‌محور** با حال‌وهوای غرب وحشی، برای **یک کیبورد**.
بدون موتور بازی، بدون فایل تصویری، بدون فایل صوتی — همه‌چیز با کد کشیده و
ساخته می‌شود.

## ▶ بازی آنلاین

**https://arshiakhedmaty.github.io/hafez-game/**

هیچ نصبی لازم نیست — لینک را باز کنید و دو نفری روی یک کیبورد بازی کنید.
این لینک با هر push خودش به‌روز می‌شود، پس همیشه آخرین نسخه است.

> آینه‌ی قدیمی Vercel از این فایل حذف شد: آن پروژه دستی دیپلوی می‌شد و
> چند کامیت عقب افتاده بود، یعنی هر کسی آن لینک را باز می‌کرد نسخه‌ی
> کهنه می‌گرفت. یک لینکِ درست بهتر از دو تا لینک است که یکی‌شان دروغ
> می‌گوید. اگر باز هم آینه خواستی، `node tools/build-vercel.js` یک فایل
> HTML مستقل می‌سازد که روی هر هاست استاتیکی بالا می‌آید.

> **این بازی فقط روی لپ‌تاپ کار می‌کند.** دو نفر، یک کیبورد، کنار هم. نسخه‌ی
> لمسی ندارد و قرار هم نبوده داشته باشد؛ اگر لینک را روی گوشی باز کنید،
> بازی همین را به‌صراحت می‌گوید به‌جای اینکه چیزی بدهد که نمی‌شود کنترلش کرد.

## اجرا روی سیستم خودت

ساده‌ترین راه: روی `index.html` دابل‌کلیک کن.

با سرور محلی (توصیه می‌شود، برای اینکه ذخیره‌سازی و فونت‌ها مطمئن‌تر کار کنند):

```bash
node server.js
```

بعد برو به `http://localhost:5173`

**میان‌بُرهای توسعه**

| آدرس | کار |
|---|---|
| `?stage=0` … `?stage=7` | پرش مستقیم به یک فصل |
| `?screen=editor` | پرش مستقیم به یک صفحه‌ی منو |
| `?lvl=…` | باز کردن مرحله‌ای که کسی ساخته و لینکش را داده |
| `preview.html` | پیش‌نمایش طراحی شخصیت‌ها (SPACE چهره، ۱ تا ۶ ژست) |
| `tools/art.html` | تولید کاور و پوستر WANTED با رندرر خود بازی |

## کنترل‌ها

| | **عرشیا** (بازیکن ۱) | **روژینا** (بازیکن ۲) |
|---|---|---|
| حرکت | `A` / `D` | `←` / `→` |
| پرش | `W` | `↑` (دو بار = پرش دوم) |
| نشستن / رها کردن طناب | `S` | `↓` |
| توانایی | `E` — پرتاب / رها کردن کمند | `/` — بالا بردن فانوس |
| بالا کشیدن روی طناب | `Shift` | — |
| بوسه (زنده کردن) | `Q` | `Right Shift` |

منوها با `W/S` یا کلیدهای جهت‌دار، تأیید با `Enter`، بازگشت با `Esc`.
`Esc` داخل بازی = مکث.

## قانون طراحی

> **عدم‌تقارن در «کنترل» است، نه در «اطلاعات».**

هر دو بازیکن یک صفحه را می‌بینند و همه‌چیز برایشان پیداست. چالش این است که
هیچ‌کدام نمی‌تواند کار آن یکی را انجام دهد:

- **عرشیا** سنگین‌تر است. جعبه‌ها را هل می‌دهد و تنها کسی است که می‌تواند
  کمند بیندازد و تاب بخورد.
- **روژینا** سبک‌تر و سریع‌تر است. پرش دوم دارد و **فانوس** دست اوست:
  تیرهای شبح‌وار فقط داخل نور او واقعی می‌شوند، پس عرشیا بدون او
  به‌معنای واقعی کلمه نمی‌تواند رد شود.

**مرگ، ریسپاون نیست.** هر کس بیفتد همان‌جا روی زمین می‌ماند و آن یکی باید
خودش را برساند و کلید بوسه را نگه دارد تا زنده‌اش کند — به قیمت از دست
دادن دائمی یک قلب از حداکثر جانش. اگر هر دو بیفتند، برمی‌گردند به آخرین
چک‌پوینت.

## بودجه‌ی حرکت

هر فاصله در `js/levels.js` بر اساس چیزی نوشته شده که موتور واقعاً تولید
می‌کند، نه حدس:

| | ارتفاع پرش | شکاف افقی | طراحی امن |
|---|---|---|---|
| عرشیا | ۹۵ px | ۱۲۲ px | ۷۰ / ۹۵ |
| روژینا (پرش دوم) | ۱۵۹ px | ۱۸۴ px | ۱۲۵ / ۱۴۵ |

هر سکویی که **۱۰۰ تا ۱۵۰ پیکسل** بالاتر از جای پا باشد، فقط مالِ روژیناست.

## حالت‌های دیگر

**SPEEDRUN** — هفت فصل عادی پشت سر هم روی یک ساعت. ساعت فقط داخل مرحله
می‌چرخد، پس منو و کارت شروع و صفحه‌ی مکث مجانی‌اند. اسپلیت زنده در برابر
بهترین ران خودت، دفتر رکورد ده‌تایی در `RECORDS`. خروج به منو یعنی پایان ران.

**LEVEL EDITOR** — با موس روی گرید ۱۰ پیکسلی می‌کشی، راست‌کلیک پاک می‌کند،
`T` تست می‌گیرد، `C` لینک را کپی می‌کند. کل مرحله داخل خود URL می‌رود
(`?lvl=…`، با base 36) و لینک مستقیم داخل موتور واقعی باز می‌شود — مرحله‌ی
ساخته‌شده هیچ مسیر جداگانه‌ای ندارد، دقیقاً همان شیئی است که `js/levels.js`
تولید می‌کند.

درها و صفحه‌های فشار با **کانال** به هم وصل می‌شوند: یک عدد روی هر دو، و در
وقتی باز می‌شود که همه‌ی صفحه‌های آن کانال پایین باشند. همان یک عدد کل مدل
ذهنی است، و روی هر دو قطعه نوشته می‌شود.

## تست‌ها

چهار ابزار جلوی برگشتن باگ‌ها را می‌گیرند:

```bash
node tools/validate.js    # آیا هر سکو واقعاً قابل رسیدن است؟
node tools/simulate.js    # ۳۴ تست روی منطق واقعی بازی
node tools/uisim.js       # ۵۲ تست روی منوها، اسپیدران، ادیتور و لینک اشتراکی
node tools/palette.js     # آیا چیزی توی بازی نامرئی است؟
```

`validate.js` مرحله را به گرافی از سطوح تبدیل می‌کند و با مدل واقعی پرتابه
راه می‌رود؛ اگر جایی برای کسی که باید آنجا بایستد غیرقابل‌دسترس باشد، شکست
می‌خورد. `simulate.js` خودِ موتور را با ورودی مصنوعی فریم‌به‌فریم اجرا می‌کند.

`uisim.js` یک لایه بالاتر است: **کل بازی** را با DOM و صدای شبیه‌سازی‌شده بوت
می‌کند و حلقه‌ی واقعی را دستی جلو می‌برد. تنها راه اثبات چیزهایی مثل «اسپیدران
واقعاً هفت فصل را زنجیر می‌کند و در دفتر رکورد می‌نشیند» همین است، چون این
خاصیتِ ماشین حالت است و نه چیز دیگر. موس ادیتور هم همان‌جا تست می‌شود.

`palette.js` هر شکل مهم بازی را در برابر **پس‌زمینه‌هایی که واقعاً پشتش
می‌آیند** می‌سنجد — سکه توی آسمان، جعبه روی زمین، خار روی ماسه — و با
اختلاف رنگ CIE ΔE قضاوت می‌کند، نه با کنتراست روشنایی؛ چون کنتراست
روشنایی برای متن ساخته شده و شنل قرمز روی زمین بنفش را اشتباه «نامرئی»
گزارش می‌کند. نتیجه‌اش این بود که پالت **خودش را تصحیح می‌کند**: هر جا
بدنه‌ی شکل گم می‌شود، خط دورِ تیره‌اش آن را نگه می‌دارد.

## انتشار

```bash
node tools/build-vercel.js        # کل بازی را در یک فایل ۷۰ کیلوبایتی می‌پزد
node tools/build-itch.js          # همان را برای itch.io بسته‌بندی می‌کند
node tools/art.html               # (در مرورگر) کاور، پوستر و اسکرین‌شات‌ها
```

**itch.io** — `build-itch.js` فایل `dist/hafez-game-itch.zip` را می‌سازد
(یک `index.html` مستقل، ~۵۳ کیلوبایت) و همه‌ی عددهایی را که فرم آپلود
می‌پرسد چاپ می‌کند: نوع پروژه HTML، ویوپورت ۹۶۰×۵۴۰، دکمه‌ی fullscreen
روشن، اسکرول‌بار خاموش، و **mobile-friendly خاموش** — چون این بازی دو
نفره روی یک کیبورد است و روی گوشی خودش همین را می‌گوید. کاور اجباری
۶۳۰×۵۰۰ در `assets/itch-cover.png` است و متن آماده‌ی صفحه در
`dist/itch-page.md`.

`build-vercel.js` سورس را مینیفای و gzip می‌کند و به‌صورت base64 داخل صفحه
می‌گذارد؛ مرورگر موقع باز شدن بازش می‌کند. نتیجه یک فایل HTML مستقل است که
از هر سرور استاتیکی کار می‌کند.

### تغییر ظاهر شخصیت‌ها

هر چیزی که مربوط به قیافه‌ی عرشیا و روژیناست در یک بلوک است: `LOOK` در
`js/config.js`. رنگ مو، مدل فر، آمبره، عینک، کلاه، لباس، گردنبند، قد و
پهنای شانه — همه از همان‌جا خوانده می‌شود و کل بازی با تغییر آن عوض می‌شود.
